# Clean reader and summary implementation plan

Status: proposal revised after a deep UX audit, 2026-10-15. This does not change the running prototype. Exact model choices, shortcuts for settings, and profile names remain provisional. See SUMMARY_UX_AUDIT.md for evidence and remaining validation.

The outcome is a reader who can understand a story, inspect the discussion and its sources, and move between stories without managing AI jobs or losing their place.

## Product decisions

- Once credentials are configured, summaries are automatic by default on intentional story entry (Enter/o/c). Moving the feed cursor or opening the external browser with O does not request a summary.
- New stories show the full pinned summary. S hides/shows it without changing comment position or stopping generation. Reopening a story preserves its visibility and reading position.
- Automatic generation can be disabled; S then starts a missing summary manually. Missing credentials produce a compact S Set up summaries hint and do not block reading. The hint opens the same settings surface used later: an OpenRouter key, Auto on, and Fast already selected. Reuse existing configuration when present. Save returns to the same story and starts its summary if Auto is on; cancel returns without losing position. A rejected key offers Edit key; temporary service failures offer Retry. No extra confirmation screen.
- Turning Auto on starts missing work for the current story. Turning it off prevents new automatic starts; already-submitted work finishes. Neither change alters visibility or comment position. Show Auto on/off in the settings entry. No feed prefetch.
- Offer two profiles, provisionally Fast and Thorough, with Fast as the proposed initial default. Each maps to a tested model and its required request settings. Both retain the same concise article and cited-discussion output format. Thorough does not mean a longer panel or guaranteed correctness.
- The profile picker states For this story and future summaries. Selecting a different profile applies to the open story and becomes the default for subsequent generation. For an existing or loading summary, the selection explicitly requests replacement even with Auto off. Existing results stay readable with their actual profile labels while replacements run. With Auto off, a story that has never requested a summary still waits for S. Choosing the profile of a retained result reuses it and supersedes an unnecessary pending replacement.
- Revisit rule: reuse matching completed results and matching pending work. With Auto on, start missing sections or replace mismatched sections unless that section already failed for the selected profile; that failure requires explicit retry. With Auto off, do not start or replace anything on entry. No automatic retry loop. A failed upgrade says, for example, Thorough unavailable; showing Fast, with Retry. Mixed-profile sections carry individual labels.
- Refresh summary is one contextual action in the same settings surface. It applies the visible settings, then recaptures sources using that profile exactly once per section, retains old results while working, and preserves reading position and visibility. Show capture time and meaningful coverage next to the relevant section. Ordinary revisits do not silently refresh successful work. No separate freshness settings or automatic refresh timer.

## Smallest architecture

Keep one Rust application with ordinary modules for reader state, source preparation, summary requests, and browser integration. Use existing reqwest/serde for direct OpenRouter calls. Use an established article-extraction library after checking its license, supported Rust version, and output on the prototype examples. No private Go dependency or local HTTP runner is required for this path.

Reader state owns the current story, visibility, positions, captured sources, and completed section results. Source preparation owns extraction, bounded input, and coverage metadata. Summary requests own prompts, concrete profile settings, response parsing, and errors. Browser integration owns only the companion pane. Model and transport choices do not leak into rendering or input navigation.

Article and discussion are two independent asynchronous tasks. Return completed section responses; token streaming is unnecessary for the current UX. Parse discussion output and validate citation IDs against supplied sources. Publish a completed discussion together with its matching source snapshot and coverage. An already-open citation keeps its original captured text and parent summary snapshot until the user returns. Stage a completed discussion replacement during that source view. When leaving the source view through Back or Feed, publish it and clear the old citation selection rather than reusing its index. On return to the summary, announce Summary updated. Reopening must consider this completed result before starting new work. The live-comment anchor stays unchanged. Enter cannot accidentally open a different source using the old selection.

Leaving a story does not cancel already-submitted summary requests. They finish into their owning story for the current CLI session; returning reuses those results or pending attempts. Abandon obsolete source preparation that has not submitted inference. Bound concurrent inference locally and admit only the active story’s latest not-yet-submitted automatic work when capacity becomes available. Show Waiting to summarize if this affects the visible story. Choose the small concurrency limit from rapid A → B → A prototype checks; do not build a persistent queue or background job service. Hiding the panel does not cancel requests. Explicit profile replacement supersedes obsolete attempts; exiting stops local work. Provider processing or billing may continue after local cancellation.

Capture profile/request settings for each attempt. Accept completion only if it still belongs to the currently owned attempt for that section. This prevents an old Fast completion, already queued before cancellation, from replacing newer Thorough state. Keep one retained result per section and the current attempt; no history of every model/profile result, persistent job system, or scheduler.

A hosted summarizer remains a possible second backend accessed through its documented API and separate credential. Preserve reader-facing result types now; implement that adapter when needed. Do not publish private packages or add a generic provider registry for this possibility.

## Existing couplings to remove during implementation

1. Browser startup currently blocks all reader entry through browser_busy in reader_actions.rs. Reader navigation and automatic summary eligibility must proceed independently. Removing that guard alone would let read_original discard a newer article request, so retain the latest desired article target while the browser is busy and reconcile it afterward. One latest-target slot is sufficient; no browser job queue. Verify that a pane cannot silently remain on A while the reader reports B as its opened article.
2. The current summary retry handler can consume r before failed live comments receive it. Route the retry intent to the failed reader components, preserving successful results. A summary retry must not accidentally refresh successful live comments and lose their position.
3. The terminal-browser integration still depends on a local bundle patch and a Ghostty config entry. Public installation and pane lifecycle need a fresh-machine check. Put platform-specific imports behind compile-time gating; a runtime cfg! branch cannot make UnixStream compile on Windows.

## Implementation order and acceptance

1. Keep representative captured inputs, summary errors, and UX sequences as acceptance examples. Compare direct OpenRouter calls using unchanged inputs/prompts before changing extraction. Establish useful Fast/Thorough request recipes rather than selecting models by marketing labels.
2. Replace private extraction with one local library. Compare normal, long, inaccessible, noisy and self-post cases. Preserve partial-source metadata and independent discussion success. Avoid adding a browser crawler or extractor fallback chain unless observed failures justify it.
3. Add configuration and lifecycle changes above. Check automatic entry versus feed movement; hide while loading; A → B → A without duplicate requests; switching profiles while loading with old completion arriving last; mixed-profile partial replacement; partial failure and targeted retry; setup/cancel/rejected-key repair; Auto on/off in the current story; refresh after an initially empty discussion; and profile replacement while a cited source is open. Opening, completion, refresh, and source/back must preserve the live-comment anchor. Keep the full content-sized pinned summary and independent summary overflow controls; do not reintroduce a compact preview.
4. Validate installation, opening, reuse, focus, and close of the optional browser pane on a clean supported system, plus the external-browser fallback. Native Ghostty acceptance remains unverified in the present environment because computer-use access is denied.

## Review outcome

Three independent Codex reviewers examined boundaries, UX/state, and implementation economy; one boundary reviewer completed a follow-up on task lifetime and profile changes. All supported direct Rust integration and deferring infrastructure. Two initially favored applying profile changes only to future generation for implementation simplicity. The synthesis chooses an explicit current-story upgrade because it matches the user's likely intent without another regenerate action. Request identity is warranted by that concrete overlapping-replacement sequence, not generic hardening.

The subsequent UX audit revised task lifetime, setup, profile feedback, refresh, and citation return behavior. Its interactive mock uses illustrative content and simulated responses. No OpenRouter integration, automatic summaries, or profile controls have been added to the running Rust prototype by this audit. Model speed, quality, cost, extraction quality, native terminal accessibility, and Ghostty lifecycle remain separate acceptance checks.
